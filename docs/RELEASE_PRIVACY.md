# 版本快照與來源專用發布規則

本專案只用一個倉庫：https://github.com/ethanlai0312-create/mango-milkshake 。不建立其他版本倉庫，也不在同一標籤下混放多個版本。

## 每個版本都是獨立快照

- 每完成一次更新，就在主分支提交一次完整源碼，並建立不可移動的 Git 標籤（`vYYYY.MM.DD.NN`）與同名 GitHub Release。
- 每個標籤對應一份完整、獨立的源碼快照；在 Release 頁面可直接下載該版本的 `Source code`（zip/tar），不需要另開倉庫，也不會覆蓋舊版本。
- 已發布標籤不覆蓋、不移動；需要修正時發布新版本。

## 只發布功能文件

倉庫只允許功能程式碼、資料庫結構遷移、必要的系統預設、設定範本與文件。禁止提交：

- 使用者資料、帳號、登入 ID、密碼雜湊或個人資料；
- 試卷、題目、答案、答卷、成績、錯題本內容；
- 上傳檔案、共享檔案、頭像、轉換檔案；
- 操作日誌、登入紀錄、在線狀態資料；
- 資料庫備份、dump、匯出檔；
- `.env`、金鑰、TLS 憑證、隧道憑證或其他環境秘密；
- 原私人部署設定與真實主機/網域/帳號識別。

## 自動檢查

推送前與 CI 都會執行 `scripts/check-release.mjs`，其中的 source-only 檢查會：

1. 檢查版本號、README、CHANGELOG、示範帳號表與每個權限的示範帳號；
2. 拒絕資料檔、備份、日誌、上傳目錄、環境檔、私鑰與憑證格式；
3. 拒絕大於 1 MiB 的檔案；
4. 掃描全部被追蹤檔案，拒絕真實網站網域、真實 Supabase 專案、真實帳號/登入 ID、私人區網位址、私人主機路徑、隧道識別與真實試卷字樣。

任何一項失敗都必須先修正，不得提交、推送或建立 Release。

公開倉庫中的檢查腳本只包含通用規則，不寫入任何站點特定的帳號、網域或主機識別。站點特定的真實帳號、登入 ID、網域、隧道與試卷字樣，由不進公開倉庫的私有發布前掃描在推送前額外檢查。
